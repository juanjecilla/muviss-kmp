# Home: a skeleton that matches, and a wave that travels

Issue #723. "Home" is Discover (`SearchRoute`).

## Problem
`LoadingSkeletonGrid` is a 12-poster grid with no headers; the loaded screen is a column (intro card, Triage entry, What's next, muted chip, For you, genre chips, Popular movies, Popular TV). The page re-flows when data lands. `Modifier.shimmer()` sweeps each item on its own.

## Proposal
1. **Same shape.** "For you" is hidden once loaded when the library has no recommendation seeds (`SearchViewModel`, `SearchScreen` drops empty carousels), so a skeleton row for it would vanish and shift everything below. Seeds are known locally before any network call: show the For you skeleton only when the library has at least one seed, otherwise omit it. `SearchViewModel` starts `loadDiscover()` independently of the library observation, so the first library value may not have arrived yet: the state carries **seeds unknown** apart from **seeds empty**, the For you row renders as a skeleton (or is decided) only once the first library emission is in, and a test makes Discover finish before the library emits and asserts the sections below never shift. Seeds do not guarantee a visible row either: `forYouFlow` can end empty after request failures or filtering, and `MediaCarousel` then hides it. That collapse is accepted as the one allowed shift, but on the initial load it happens **once, when the result is known to be empty**. A later empty result is valid and allowed: `SearchViewModel` recomputes For you when the library, triage decisions or muting change, so saving the last recommendation or removing the last seed legitimately empties a row that showed content. A **failed** request with no cached copy is not an empty result: it shows the inline "Couldn't load" row with Retry from the offline-cache proposal (the full-screen error applies only once **every** section has settled with no content and at least one failure, never because one section, For you included, failed first: the screen concludes "nothing available" when all requests have completed, and a test makes For you fail before the others finish and asserts the other sections still render; the inline row is for a section failing next to sections that did load), never a collapsed row, so the failure and its recovery action stay visible; only a successful empty result collapses. Tests cover seeds with an empty initial result (skeleton replaced by nothing in one step) and a later empty result. The same rule holds for the other skeleton rows: `MediaCarousel` and `GenreChipRow` hide an empty list, so a shelf that muting filters to nothing collapses once its result is known, accepted for the same reason and tested the same way, rather than keeping an empty header.
    Local parts (intro, Triage entry, What's next, muted chip) need no network and render for real. Poster placeholders reserve the **caption** too: `PosterCard` adds 6 dp of top padding and two title lines, and `PosterSkeleton` covers only the image today, so the placeholder gets caption bars of the same total height, computed with the same font scaling, or each carousel shifts the sections below it when content loads (a golden at 1.0 and at a large font scale pins it). Network sections render skeleton rows under their real headers, each with its **own** placeholder shape: poster cards (110 dp `PosterCard`) for For you and the Popular carousels, and chip-sized placeholders for the movie and TV genre sections, which load from the network but render `GenreChipRow` chips, not posters. Counts that fit the width, so nothing moves on load.
2. **A wave.** One gradient brush positioned in window coordinates, animated across the root, so the highlight reaches each skeleton in turn. Items read their offset from `LocalShimmer` rather than each owning an animation, which also makes it one animation, not twelve.
3. **Standalone library.** `:lib:shimmer`: Compose only, no `com.codingpit.muviss` import. API: a `ShimmerHost` (provides the clock and angle), `Modifier.shimmer(...)`, colors/duration/direction as parameters, a reduced-motion flag as a plain boolean. `:core:designsystem` keeps `PosterSkeleton`/`TextLineSkeleton`/`RowSkeleton` and feeds them Muviss colors and the reduce-motion switches (#394, EPIC 52): reduced motion → a static fill.

## Check before building
- Register the module: `settings.gradle.kts` includes modules explicitly and does not discover `lib/`, so add `:lib:shimmer` there, or the project dependency cannot resolve (the graph check can accept a prefix without the project being registered).
- `settings.gradle.kts`'s module loop and `verifyModuleGraph` assume `feature/`, `core/`, `app/`; confirm a `lib/` prefix is accepted, or extend the rule.
- `muviss.kmp.compose` sets up Compose Resources and `androidResources`; the library likely wants `muviss.kmp.library` + Compose plugin only.
- Web: a full-screen animated brush on canvas; measure.
- Offscreen compositing on Android for `graphicsLayer` brushes.

## Corner cases
Cache hit (see Discover cache) must not flash a skeleton; wide screens (grid vs. rows); right-to-left (wave direction flips); large font scale (header heights); TalkBack announces "Loading", not 40 skeleton nodes; rotate mid-animation keeps phase.

## Tests
Golden light/dark with a paused `mainClock`; wave position at two clock times differs and is continuous across two siblings; reduce-motion is static; a guard that the lib has no Muviss imports; `ShimmerSweepTest` migrates.
